## 👋 Hello there!

FormLens reads scanned forms and PDFs with document models that run on your own machine, with no cloud calls, and
returns their text and the fields you ask for. This is the monorepo: the service, the web app and the client that
connects them. It is managed with [Nx](https://nx.dev) and npm workspaces.

The Python package, its CLI and the image are still called `formlens`; `form-lens` is only the repository.

## ✨ Features

### 🚀 What You Get

- **📄 Local document parsing** — `POST /v1/documents/parse` in `apps/api` reads a PDF, PNG, JPEG or TIFF with Granite-Docling through [Docling](https://github.com/docling-project/docling), and no document leaves the machine
- **🧩 Form templates and extraction** — describe a form's fields once (`/v1/templates`), submit a document with the template (`POST /v1/extractions`) and read the validated values back later; a local [Ollama](https://ollama.com) model fills the fields
- **🖥️ A web app for the results** — `apps/studio` lists the form templates of the API, with the Szum-Tech Design System, Storybook and Playwright tests
- **🔗 One contract, one client** — `apps/api/openapi.json` is generated from the code and checked for drift; `packages/api-client` is generated from it with Orval, and CI fails when it is stale

### 🛠️ Repository

- **🎯 Affected-only CI** — `.github/workflows/ci.yml` asks Nx which apps a change touches and runs only their jobs
- **🔒 Audits and code scanning** — a dependency audit job that always runs, and CodeQL for JavaScript and Python
- **📦 Independent releases** — release-please versions and tags each app from Conventional Commits
- **🐳 Docker images** — `apps/api` and `apps/studio` each have a Dockerfile, and Nx targets build them

## 🎯 Getting Started

### 📋 Prerequisites

Before you begin, ensure you have the following installed:

- **Node.js** 26 (see `.nvmrc`) with npm
- **[uv](https://docs.astral.sh/uv/)** for the Python API
- **Docker**, only to build the images
- **Git** for version control

### 📦 Installation

#### 1. Clone the Repository

```bash
git clone https://github.com/JanSzewczyk/form-lens.git
cd form-lens
```

#### 2. Install Dependencies

```bash
npm ci                                  # the Studio, the client and Nx
npx nx run api:install                  # uv sync --locked in apps/api
npx nx graph                            # how the projects relate
```

#### 3. Run the API

The API needs the document model first: run `make download-models` in `apps/api` (see its
[README](apps/api/README.md)).

```bash
npx nx run api:serve                    # http://localhost:8000
```

#### 4. Run the Studio

```bash
cp apps/studio/.env.example apps/studio/.env.local   # FORMLENS_API_URL points at the API
npm run dev -w @form-lens/studio                      # http://localhost:3000
```

The API is optional for the page to load: without it the home page says the API is not available.

## 📃 Commands

Run an app's own commands from its folder: `make ...` and `uv ...` in `apps/api`, `npm run ... -w @form-lens/studio`
for the Studio. `apps/api` keeps its Makefile as the single source of truth; the Nx targets call it.

### 🔧 From the Repository Root

| Command | What |
| --- | --- |
| `npx nx run api:check` | Everything `make check` runs in `apps/api`: format, lint, types, import contracts, tests, OpenAPI drift |
| `npx nx run-many -p studio api-client -t generate:check type-check biome:ci knip:ci test:unit build` | The Studio checks |
| `npx nx affected -t check type-check` | The checks of the projects a change touches (`NX_BASE=origin/main`) |
| `npx nx run api:openapi` | Regenerate `apps/api/openapi.json` |
| `npm run generate -w @form-lens/api-client` | Regenerate the client after the API contract changed |
| `npx nx run api:docker-build`, `npx nx run studio:docker-build` | Build the images |

### 🐍 `apps/api` (Makefile)

| Group | Targets |
| --- | --- |
| Setup | `make install`, `make download-models`, `make migrate`, `make clean` |
| Run | `make run`, `make docker-build`, `make docker-run` |
| Quality | `make format`, `make lint`, `make typecheck`, `make imports`, `make audit`, `make check` |
| Tests | `make test`, `make test-models`, `make schemathesis`, `make evaluate` |
| Contract | `make openapi`, `make openapi-check`, `make api-lint`, `make api-breaking`, `make api-check` |

### ⚛️ `apps/studio` (npm scripts)

| Group | Scripts |
| --- | --- |
| Run | `dev`, `build`, `start`, `analyze` |
| Quality | `type-check`, `biome:check`, `biome:ci`, `biome:fix`, `biome:format`, `biome:lint`, `knip` |
| Tests | `test`, `test:unit`, `test:storybook`, `test:e2e`, `test:coverage`, `test:watch`, `test:ui` |
| Storybook | `storybook:dev`, `storybook:build`, `storybook:serve` |

Storybook (`storybook:build`, `test:storybook`) and Playwright (`test:e2e:ci`, after `build`) need browsers and run
separately.

After an API contract change run `make openapi` in `apps/api`, then `npm run generate -w @form-lens/api-client`.
`packages/api-client/src/generated` is generated; never edit it.

## 🔄 CI and Releases

`.github/workflows/ci.yml` asks Nx which apps a change touches and runs only their jobs. Branch protection requires
two checks by name: `Check ✅` (the gate over the other jobs; a job skipped because its app is not affected counts as
passed) and `Audit 🔒` (dependency audits, always run). Renaming a job leaves pull requests waiting for a status that
never arrives. CodeQL covers JavaScript and Python.

Each app is released on its own by [release-please](https://github.com/googleapis/release-please) from the
Conventional Commits on `main`; see [docs/releases.md](docs/releases.md) for versions, tags (`api-vX.Y.Z`,
`studio-vX.Y.Z`) and the GitHub App the release workflow needs.

## 📁 Project Structure

```
form-lens/
├── apps/
│   ├── api/                # FastAPI service (Python, uv, Makefile)
│   └── studio/             # Next.js web app (npm workspace)
├── packages/
│   └── api-client/         # Orval-generated TypeScript client of the API
├── docs/                   # releases.md, templates.md
├── .github/workflows/      # ci.yml, codeql.yml, release.yml
├── .claude/rules/          # Studio rules for Claude Code (apps/studio only)
├── nx.json                 # Nx targets, caching and named inputs
├── package.json            # npm workspaces: apps/studio, packages/api-client
├── release-please-config.json
└── .nvmrc                  # Node 26
```

### Key Directories

- **`apps/api/`** — a standalone uv project with its own `uv.lock`; the Python package, CLI and image are `formlens`
- **`apps/studio/`** — the Next.js app; one `package-lock.json` for the whole repository lives at the root
- **`packages/api-client/`** — `src/generated` is generated from `apps/api/openapi.json`
- **`docs/`** — [releases.md](docs/releases.md) and [templates.md](docs/templates.md), the templates the apps started from

### Important Configuration Files

- **`nx.json`** — target defaults and cache inputs; Nx project names are `api`, `@form-lens/studio` and `@form-lens/api-client`
- **`release-please-config.json`** and **`.release-please-manifest.json`** — per-app versions and changelogs
- **`CLAUDE.md`** — conventions for working in the repository; each app has its own

## 🤝 Contributing

Contributions are welcome!

1. Fork the repository
2. Create a feature branch (`git checkout -b feat/amazing-feature`)
3. Make your changes and run the checks of the app you touched (see [Commands](#-commands))
4. Commit using [Conventional Commits](https://www.conventionalcommits.org/): `type(scope): imperative summary`, with the scope `api`, `studio` or `api-client` for a change in one app; release-please builds versions and changelogs from them
5. Open a Pull Request; `Check ✅` and `Audit 🔒` must pass

Add npm dependencies with `npm install <pkg> -w <workspace>`. The uv version is pinned in `apps/api/Dockerfile` and in
`UV_VERSION` of each workflow that sets it.
